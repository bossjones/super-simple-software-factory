# Existing SSSF Architecture Seams

verified_on: 2026-09-14
scope: This page records the current repo seams that the Copilot port must preserve and excludes new runtime design that is not yet implemented.

- The product currently lives as a skill under [`.claude/skills/sssf/`](../.claude/skills/sssf/), and the repository README describes that skill as the thing that gets stamped into target repos. Primary sources: [README.md](../README.md) and [`.claude/skills/sssf/cookbooks/install.md`](../.claude/skills/sssf/cookbooks/install.md).
- Installation is template stamping, not dynamic scaffolding. [`scripts/install.py`](../.claude/skills/sssf/scripts/install.py) copies [`templates/adws/`](../.claude/skills/sssf/templates/adws/), [`templates/prompt_engineering/`](../.claude/skills/sssf/templates/prompt_engineering/), [`templates/harness_engineering/`](../.claude/skills/sssf/templates/harness_engineering/), [`templates/sssf.config.yaml`](../.claude/skills/sssf/templates/sssf.config.yaml), [`.env.sample`](../.claude/skills/sssf/templates/env.sample), and the template [`justfile`](../.claude/skills/sssf/templates/justfile).
- The roster seam is [`templates/sssf.config.yaml`](../.claude/skills/sssf/templates/sssf.config.yaml): defaults define coding agent, model, thinking, tools, protected files, and `data_dir`, while each agent overrides only what differs. `agents.load_config()` and `agents.validate()` merge those defaults and fail fast before anything spawns; source: [`templates/adws/adw_modules/agents.py`](../.claude/skills/sssf/templates/adws/adw_modules/agents.py) and [`.claude/skills/sssf/references/config.md`](../.claude/skills/sssf/references/config.md).
- The workflow primitive is `run.phase(...)`. [`runner.py`](../.claude/skills/sssf/templates/adws/adw_modules/runner.py) uses the same context-manager primitive for engineer, agent, and code phases, and `finish()` separates "all phases ran" from "the run is acceptable." That seam is core to the port because it keeps control in code instead of the model.
- Agent execution already assumes a bounded runtime module. [`agents.execute()`](../.claude/skills/sssf/templates/adws/adw_modules/agents.py) renders prompts, calls the coding-agent adapter, parses a typed envelope, retries JSON and gate failures in the same session, records usage, and writes handoff artifacts. The port changes the adapter, not the workflow contract.
- Repository write enforcement is already host-owned. [`permissions.py`](../.claude/skills/sssf/templates/adws/adw_modules/permissions.py) snapshots the working tree before a call, compares it after the call, rolls back unauthorized changes where possible, and treats `tools` as capability hints rather than a sandbox. That exact boundary must survive the Copilot port.
- Observability is already split into raw files plus SQLite. [`session.py`](../.claude/skills/sssf/templates/adws/adw_modules/session.py) pins or creates the ADW session, and [`tracer.py`](../.claude/skills/sssf/templates/adws/adw_modules/tracer.py) writes JSONL plus SQLite in WAL mode so a running workflow can be observed without a separate ingest service.
- Deterministic quality checks are already code phases. [`quality.py`](../.claude/skills/sssf/templates/adws/adw_modules/quality.py) is intentionally placeholder-driven today, but it establishes the seam that known commands run as code, not as another agent phase.

Refresh from the linked repo files above before later tasks move paths or rename modules, because these seams are what the Copilot port is supposed to preserve.
