# Pi to Copilot Migration Matrix

verified_on: 2026-09-14
scope: This page maps the Pi-backed factory surfaces to Copilot-native equivalents and calls out the host responsibilities that do not move into Copilot.

| SSSF need | Pi baseline | Copilot source of truth | Port decision |
|---|---|---|---|
| Headless agent execution | Pi provides print, JSON, and RPC modes for non-interactive control. ([usage](https://pi.dev/docs/latest/usage), [json](https://pi.dev/docs/latest/json), [rpc](https://pi.dev/docs/latest/rpc)) | Copilot CLI provides `-p/--prompt` for one-shot runs, and the Python SDK provides JSON-RPC session control through `CopilotClient`. ([CLI programmatic reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference), [Python README](https://github.com/github/copilot-sdk/blob/main/python/README.md)) | Move runtime integration to the official Python SDK, not shelling out to CLI text output. |
| Stable session identity | Pi persists sessions by default and exposes `--session` / `--fork`. ([usage](https://pi.dev/docs/latest/usage)) | Copilot resume depends on `create_session(..., session_id=...)` plus `resume_session(session_id, ...)`, despite the persistence guide's conflicting prose. ([session persistence](https://github.com/github/copilot-sdk/blob/main/docs/features/session-persistence.md)) | Keep `agent_map.json` as the SSSF lookup table and always supply deterministic session IDs. |
| Same-session correction turns | Pi continues a named session through the same runtime session file/ID. ([rpc](https://pi.dev/docs/latest/rpc)) | Copilot keeps a session live across `send`, `send_and_wait`, `resume_session`, and `disconnect()`. ([Python README](https://github.com/github/copilot-sdk/blob/main/python/README.md), [session persistence](https://github.com/github/copilot-sdk/blob/main/docs/features/session-persistence.md)) | Corrections stay in the same Copilot session; no cold restart for parse or gate failures. |
| Streaming trace events | Pi emits JSONL deltas and terminal message/tool events. ([json](https://pi.dev/docs/latest/json)) | Copilot emits persisted and ephemeral session events, including tool lifecycle and `session.idle`. ([streaming events](https://github.com/github/copilot-sdk/blob/main/docs/features/streaming-events.md)) | Normalize Copilot events into SSSF's existing `agent_start` / `tool_call` / `handoff` / `agent_end` / `error` vocabulary. |
| Mechanical completion signal | Pi's harness can watch terminal events and explicit abort RPCs. ([rpc](https://pi.dev/docs/latest/rpc)) | Copilot's mechanical completion signal is `session.idle`, and `send_and_wait()` waits for that event. ([streaming events](https://github.com/github/copilot-sdk/blob/main/docs/features/streaming-events.md), [`session.py`](https://github.com/github/copilot-sdk/blob/main/python/copilot/session.py)) | Trust idle, not model-authored "done" text. |
| Deadline handling | Pi RPC exposes `abort`. ([rpc](https://pi.dev/docs/latest/rpc)) | Copilot `send_and_wait(timeout=...)` stops waiting but does not cancel work; `session.abort()` is the actual cancellation call. ([`session.py`](https://github.com/github/copilot-sdk/blob/main/python/copilot/session.py)) | Preserve host-owned time budgets and call `abort()` explicitly on deadline. |
| Tool and extension surface | Pi exposes built-in tools, extension tools, and extension commands. ([usage](https://pi.dev/docs/latest/usage), [extensions](https://pi.dev/docs/latest/extensions)) | Copilot SDK exposes built-in tools, custom tools, MCP servers, and custom agents with their own tool lists. ([Python README](https://github.com/github/copilot-sdk/blob/main/python/README.md), [MCP docs](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers), [custom agents](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents)) | Replace Pi-specific extension assumptions with Copilot-native tools, MCP, hooks, and skill/plugin packaging. |
| Skills portability | Pi supports the Agent Skills standard but tolerates some violations. ([skills](https://pi.dev/docs/latest/skills)) | Copilot supports the open Agent Skills model and documents standard skill locations and `SKILL.md` expectations. ([about agent skills](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills), [add skills](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-skills), [Agent Skills specification](https://agentskills.io/specification)) | Keep `sssf` as a standards-compliant Agent Skill instead of a Pi-only capability. |
| Packaged distribution | Pi packages can bundle extensions and skills. ([Pi docs index](https://pi.dev/docs/latest)) | Copilot plugins bundle agents, skills, hooks, MCP, and LSP resources; new portable work should use Agent Plugins 1.0. ([about plugins](https://docs.github.com/en/copilot/concepts/agents/about-plugins), [plugin reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference), [Agent Plugins spec](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)) | Repackage SSSF as a Copilot-first Agent Plugins 1.0 plugin with a standard skill. |
| Repo write policy | Pi itself has no built-in permission boundary and suggests sandboxing for stronger isolation. ([Pi repo](https://github.com/earendil-works/pi)) | Copilot offers permission flags, callbacks, hooks, trusted directories, and preview sandboxes, but none of those alone proves repo writes stayed inside policy. ([CLI programmatic reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-programmatic-reference), [hooks](https://docs.github.com/en/copilot/concepts/agents/hooks), [about Copilot CLI](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-copilot-cli)) | Preserve SSSF's post-run snapshot and rollback enforcement as the authoritative write-policy check. |
| Experimental convenience surfaces | Pi already exposes session forking in its normal session model. ([usage](https://pi.dev/docs/latest/usage)) | Copilot documents `/fleet`, but Task 1 found no stable session-fork contract in the lifecycle sources it must depend on. ([fleet](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/fleet), [session persistence](https://github.com/github/copilot-sdk/blob/main/docs/features/session-persistence.md), [Python README](https://github.com/github/copilot-sdk/blob/main/python/README.md)) | Exclude fleet and fork from the core ADW path until a pinned release and tests make them safe to depend on. |

Refresh from the linked Pi and Copilot sources before changing this matrix; later implementation tasks should treat it as the working source of truth.
