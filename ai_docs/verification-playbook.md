# Verification Playbook

verified_on: 2026-09-14
scope: This page defines the verification loop later tasks should follow, with Task 1 centered on documentation and URL validation rather than code-level TDD.

- Task 1's verification loop is documentation-first: read the smallest relevant page in this `ai_docs/` corpus, make the change, run `just docs-check`, and fix every actionable link failure before calling the work done. The command exists to keep later tasks grounded in the same validated source set; source: [README.md](README.md), [copilot-sessions-events.md](copilot-sessions-events.md), and the approved design in [`docs/superpowers/specs/2026-09-14-copilot-software-factory-design.md`](../docs/superpowers/specs/2026-09-14-copilot-software-factory-design.md).
- Before runtime code changes, the design requires checking create, resume, event, idle, disconnect, and abort semantics against the official Python SDK docs and source, and recording conflicts instead of smoothing them over. The required live sources are the [Python README](https://github.com/github/copilot-sdk/blob/main/python/README.md), [Streaming events](https://github.com/github/copilot-sdk/blob/main/docs/features/streaming-events.md), [Session resume and persistence](https://github.com/github/copilot-sdk/blob/main/docs/features/session-persistence.md), and [`python/copilot/session.py`](https://github.com/github/copilot-sdk/blob/main/python/copilot/session.py).
- When production behavior exists, later tasks should prefer targeted deterministic tests over prose-only confidence. For this port that means keeping typed-envelope parsing, write-policy enforcement, normalized tracing, and timeout-abort behavior under repository tests rather than relying on an interactive transcript; source: [copilot-sessions-events.md](copilot-sessions-events.md), [copilot-tools-hooks-permissions.md](copilot-tools-hooks-permissions.md), and [sssf-architecture.md](sssf-architecture.md).
- URL validation is not optional after Task 1 because every later task depends on these docs as factual inputs. The operating rule is simple: if a link is broken and checkable, fix it; if it is real but not automatically checkable, document the endpoint behavior and exclude only that case in `lychee.toml`.
- Fleet, session-fork behavior, and any other version-sensitive convenience surface must stay outside the core path until the pinned SDK/runtime/CLI combination is validated against the actual release being adopted; source: [copilot-sessions-events.md](copilot-sessions-events.md), [copilot-agents-skills-plugins-mcp.md](copilot-agents-skills-plugins-mcp.md), and the approved design in [`docs/superpowers/specs/2026-09-14-copilot-software-factory-design.md`](../docs/superpowers/specs/2026-09-14-copilot-software-factory-design.md).

Refresh the cited primary sources, then rerun the repository validation command before and after every later task that changes the grounding corpus or the Copilot runtime.
